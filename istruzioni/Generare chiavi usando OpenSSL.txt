Creare da un terminale (finestra dos)la chiave private con il comando:  openssl genpkey -algorithm RSA -out private_key.pem -pkeyopt rsa_keygen_bits:2048

Creare la chiave pubblica a partire da quella privata con il comando:   openssl rsa -pubout -in private_key.pem -out public_key.pem

posso farlo nel seguente modo:

CONFIG_BOOTLOADER_MCUBOOT=n in prj.conf

This will disable MCUboot entirely during your debug sessions.

oppure

CONFIG_MCUBOOT_BOOTLOADER_MODE_DIRECT_XIP=y

CONFIG_BOOT_DIRECT_XIP=y

In this mode, MCUboot will boot the image directly from a given slot without performing any swap operations.

oppure:

Increase the required security counter: If you're using a security counter for anti-rollback protection, you can temporarily set a very high value in your prj.conf:

CONFIG_MCUBOOT_HW_DOWNGRADE_PREVENTION=y

CONFIG_MCUBOOT_HW_DOWNGRADE_PREVENTION_COUNTER_VALUE=0xFFFFFFFF

This will prevent MCUboot from considering any update valid during your debugging.

oppure:

Use a debug build of MCUboot: You can create a debug configuration for MCUboot that skips the update process. In your child_image/mcuboot/mcuboot.conf, add:

CONFIG_MCUBOOT_SKIP_IMAGE_VERIFICATION=y

This will skip the image verification process, effectively preventing updates during debug.

What prevents that at every startup I have no uplad?
After a successful update, MCUboot has mechanisms in place to prevent unnecessary updates on subsequent reboots. Here's how it works and what prevents uploads at every startup:
Image Verification: MCUboot verifies the integrity and authenticity of the firmware image before applying any update. If the image in the secondary slot (your external NOR flash) is identical to the one in the primary slot, no update will occur.
Version Checking: MCUboot compares the version numbers of the images in the primary and secondary slots. An update only occurs if the version in the secondary slot is newer than the one in the primary slot.
Security Counter: If you're using a security counter for anti-rollback protection, MCUboot will only update to images with a higher security counter value.
Swap Status: After a successful update, MCUboot marks the update as complete in its metadata. This prevents the same update from being applied again on subsequent boots.
Image Confirmation: In some configurations, MCUboot requires the new image to be explicitly confirmed after an update. Until confirmation, it may revert to the previous image on the next boot.
To ensure that updates don't occur unnecessarily at every startup, you should:
Implement proper version control in your firmware images.
Use the security counter feature if anti-rollback protection is required.
Consider implementing an image confirmation mechanism in your application.
If you're still experiencing unwanted updates, you might want to check your MCUboot configuration. For example, you can add these lines to your prj.conf or mcuboot.conf:

CONFIG_BOOT_UPGRADE_ONLY=y
CONFIG_BOOT_UPGRADE_ONLY_SECURITY_COUNTER=y
These configurations ensure that MCUboot only performs upgrades (not downgrades) and uses the security counter for additional protection.
For more detailed information on configuring MCUboot to prevent unnecessary updates, you can refer to the Downgrade prevention documentation.
MCUboot and NSIB provides additional information on MCUboot's behavior and configuration options in Nordic Semiconductor projects.
